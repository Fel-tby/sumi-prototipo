# Segurança

## Relato de vulnerabilidades

Vulnerabilidades não devem ser publicadas em issues abertas. O relato deve ser encaminhado diretamente aos responsáveis institucionais pelo projeto.

## Regras básicas

- Segredos não são versionados.
- Credenciais administrativas permanecem no backend.
- Toda entrada externa é validada no servidor.
- Autorizações são aplicadas pela API.
- Arquivos são validados antes do armazenamento.
- Ações críticas geram eventos de auditoria.
- Dependências são verificadas continuamente.
